# Huawei_DPD Project Layout

This project is now organized close to the OpenDPD style while preserving all
existing scripts.

## Active workflow

- `main.py`: root entry placeholder, kept at project root like OpenDPD.
- `steps/`: active training, evaluation, and current experiment scripts.
- `steps/evaluate_unified.py`: unified checkpoint evaluator.

Run the unified evaluator from the project root:

```powershell
& D:\anconda\envs\pytorch\python.exe steps\evaluate_unified.py
```

## Reusable code

- `backbones/`: candidate network/backbone implementations.
- `modules/`: support scripts for environment checks and dataset visualization.
- `datasets/`: dataset and LUT analysis scripts.
- `steps/figures/`: figures generated by current active experiments.
- `datasets/figures/`: dataset and LUT analysis figures.

## Archived experiments

- `other/`: historical or currently unused experiment scripts. Nothing was deleted.
- `other/figures/`: figures from archived experiments.
- `checkpoints/archive/`: old root checkpoints.
- `checkpoints/archive_data/`: old checkpoints that were previously under `data/`.

Only the current best competition-compliant checkpoint is kept at the project
root:

- `best_raw_model_A.pth`: 782 real multipliers, about -34.53 dB full-sequence NMSE.

The early lightweight PA surrogate is also kept at the project root for
comparison, but it is not used by the default ACLR metric:

- `best_surrogate_pa.pth`

Transformer PA teacher checkpoints are archived for optional research use:

- `checkpoints/archive/teacher_pa_model.pth`
- `checkpoints/archive/true_pa_model.pth`

## Unified Evaluation Rule

The evaluator always reports:

- checkpoint name
- linear NMSE
- dB NMSE
- real multiplier count
- fitted-output PSD plot
- target `y` ACLR
- predicted `f(x)` ACLR

ACLR is computed as the leakage ratio:

```text
ACLR_dBc = mean PSD(adjacent leakage band) - mean PSD(main channel band)
```

The lower and upper adjacent channels are both evaluated, and the summary uses
the worse of the two as `*_aclr_worst_db`; for leakage-ratio ACLR, worse means
the larger value because `-30 dBc` is worse than `-50 dBc`.

Default ACLR settings follow the dataset description:

- sample rate: `491.52 MHz`
- signal bandwidth: `200 MHz`
- main band: `[-100, 100] MHz`
- lower low-side band: `[-245, -180] MHz`
- upper low-side band: `[180, 245] MHz`
- target: worst ACLR <= `-45 dBc`

The default ACLR evaluator does not run an extra PA cascade. It computes PSD
directly from target `y` and predicted `f(x)`, matching the current
interpretation that the dataset target is already the processed answer.
